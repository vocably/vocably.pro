# packages/www

## Page styles

- Do NOT add new SCSS files to `src/styles/sections/` for page-specific styles.
- Put page styles in a `<style>` block inside the page's handlebars template (`src/pages/*.handlebars`), right after the `{{#> layout ...}}` opening.
- Styles shared by several pages go into a partial in `src/partials/` (e.g. `ise-styles.handlebars`) and are included with `{{> partial-name }}`.
- Use the CSS variables declared on `:root` in `src/styles/_global.scss` (sourced from `@vocably/styles/_variables.scss`) instead of SASS variables, e.g. `var(--v-color-primary)`, `rgba(var(--v-color-primary-rgb), 0.1)`, `var(--v-headings-font-family)`. Add a new variable there if one is missing.
- Bootstrap mixins aren't available in `<style>` blocks; use plain media queries (`sm` = 576px, `md` = 768px, `lg` = 992px).

## Validating changes

- Every change in `packages/www` must be validated in the browser on http://localhost:8050 before reporting it done.
- The dev server is started with `npm start` from `packages/www` (webpack dev server on port 8050). Check whether it's already running first; start it in the background if not.
- Open the affected page(s), check that the change renders as intended (desktop and ~400px mobile width when layout is touched), and check the console for errors.

## Sitemap

- A page's `lastmod` in `sitemap-main.xml` is the date of the last git commit touching its `.handlebars` file (`seo/buildMainSitemap.ts`); changed `lastmod` values are also submitted to IndexNow on deploy.
- To change a page without bumping its `lastmod` (e.g. visual-only changes), put `[skip sitemap]` in the commit message.
- If a commit already landed without the marker, add its hash to `ignoredCommits` in `seo/buildMainSitemap.ts` — it's then ignored for every page's `lastmod`.

## SEO search pages

- `/<pair>/<word>-in-<language>.html` (e.g. `/de-en/apple-in-german.html`) are not built here: `packages/seo-backend` renders them on demand from `search.html` and the page's own search data, read per request from the SEO bucket as `<pair>/<word slug>.json` (synced from `seo/search-data/<pair>.json` by `scripts/seo-upload-search-data.mts` on deploy), behind CloudFront (`platform/seo.tf`).
- Every `seo/search-data/<pair>.json` is a language pair (generated by `scripts/build-seo-search-data.mts`); the build only generates `dist/<pair>/sitemap.xml` from it (`seo/buildSeoSitemaps.ts`). A page's `lastmod` changes when its data does.
- To see them locally, run `npm run serve` in `packages/seo-backend` next to `npm start` here; the dev server proxies `/<pair>/` to it.
